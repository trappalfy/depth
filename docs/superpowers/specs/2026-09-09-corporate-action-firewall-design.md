## 1. Проверенные факты

Всё ниже получено прямыми вызовами к мейннету 2026-09-09, а не из документации. Каждая строка воспроизводима через `eth_call` к `https://rpc.mainnet.chain.robinhood.com`.

### 1.1 Токен реализует ERC-8056

Проверено на TSLA `0x322F0929c4625eD5bAd873c95208D54E1c003b2d`:

| Функция | Селектор | Значение на 2026-09-09 |
|---|---|---|
| `uiMultiplier()` | `0xa60bf13d` | `1e18` |
| `newUIMultiplier()` | `0xdc767007` | `1e18` |
| `effectiveAt()` | `0x97a4064f` | `0` |
| `oraclePaused()` | `0x7706ba52` | `false` |
| `paused()` | `0x5c975abb` | `false` |
| `decimals()` | `0x313ce567` | `18` |

Пауз **две** и они независимы: `oraclePaused()` — заморожен фид, `paused()` — заморожен сам токен. Форкнутый DeFi-протокол не проверяет ни одну.

### 1.2 Семантика `effectiveAt` — контринтуитивная

`effectiveAt()` хранит время **последнего применённого** изменения, а не признак ожидающего. У токенов с историей оно ненулевое и лежит в прошлом:

| Тикер | `uiMultiplier` | `newUIMultiplier` | `effectiveAt` |
|---|---|---|---|
| CRWD | 4.00000000 | 4.00000000 | 2026-07-02 (в прошлом) |
| ORCL | 1.00221091 | 1.00221091 | 2026-07-27 (в прошлом) |
| AAPL | 1.00056608 | 1.00056608 | 2026-08-14 (в прошлом) |
| TSLA | 1.00000000 | 1.00000000 | `0` |

**Корректный признак покоя:** `newUIMultiplier() == uiMultiplier()`.
**Корректный признак ожидания:** `newUIMultiplier() != uiMultiplier()`, а `effectiveAt()` указывает момент переключения.

Использовать `effectiveAt == 0` как «действия нет» — ошибка, ломающаяся на любом токене с историей.

CRWD `0xea72Ecca2d0f6bFA1394DBBCff85b52CD4233931` имеет `uiMultiplier = 4.0` — применённый сплит 4:1. Сценарий не гипотетический, он в прошлом. Всего 13 из 194 токенов имеют множитель, отличный от 1.0.

## 2. Проблема

Цена содержит множитель, баланс — нет. Отсюда две валидные конвенции и две ошибочные:

| Баланс | Цена | Результат |
|---|---|---|
| `balanceOf()` | Chainlink | верно |
| `balanceOfUI()` | Chainlink | множитель дважды → переоценка залога |
| `balanceOf()` | REST `/prices` | недооценка → ложные ликвидации |
| `balanceOfUI()` | REST `/prices` | верно |

Ошибается не наивный форк, а добросовестный интегратор: тот, кто прочитал про множитель и применил его вручную поверх уже скорректированной цены. На CRWD это переоценка в 4 раза.

Но основной ущерб — не редкий сплит, а **режим по умолчанию**:

1. **Суточный heartbeat на круглосуточной цепочке.** Порог свежести в час → фид легально молчит до 24 часов → health-check реветит → рынок в DoS, ликвидации невозможны. Порог в сутки → протокол считает залог по цене суточной давности.
2. **Выходные.** Акции торгуются 24/5, цепочка живёт 24/7. Каждую субботу и воскресенье цена несвежая by design.
3. **Окно корпоративного действия.** Крупные действия обрабатываются через паузу оракула со снятием **вручную**, то есть неограниченной длительности.

Пункты 1 и 2 срабатывают у каждого клиента еженедельно. Это делает продукт нужным с первого дня, а не «когда случится сплит».

## 3. Продукт

Один immutable-контракт на пару «токен + фид», совместимый с `AggregatorV3Interface`. Протокол-клиент меняет **один адрес оракула** через governance. Код не трогает, аудит не переделывает.

Внутри адаптер делает то, чего не делает сырой фид: отслеживает корпоративные действия, обе паузы, разрывы цены и режим рынка, и не даёт этому превратиться ни в ложную ликвидацию, ни в заморозку рынка.

---

## 4. Архитектура

### `StockOracleAdapter`

Ядро. Immutable, без владельца, без ролей, без прокси; параметры зашиты в конструкторе.

```solidity
interface IStockOracleAdapter is AggregatorV3Interface {
    enum Status { NORMAL, OFF_HOURS, CORPORATE_ACTION, DESYNC, TOKEN_HALTED, SEQUENCER_DOWN, UNSAFE }

    function status()     external view returns (Status);
    function observedAt() external view returns (uint256);  // честное время наблюдения рынка
    function valueOf(uint256 rawAmount)  external view returns (uint256);  // USD, 18 dec
    function valueOfUI(uint256 uiAmount) external view returns (uint256);
    function commit() external;   // permissionless срез, привилегий не даёт
    function token() external view returns (address);
    function feed()  external view returns (address);
}
```

### `AdapterFactory`

CREATE2, permissionless. Адрес выводится детерминированно из `(token, feed, params)`. Реестра нет и владельца нет: клиент пересчитывает адрес сам и убеждается, что подмена невозможна.

### `FirewallLens`

View-агрегатор для мониторинга. **Вне доверенного пути**, на него ничего не завязано. Для сайта не нужен — его роль закрывает Multicall3.

### `ValuationLib`

Библиотека, отдельно не деплоится. Закрывает матрицу конвенций: `valueOf` принимает сырой баланс, `valueOfUI` — UI-баланс, применить множитель дважды физически нельзя.

## 5. Автомат состояний

На каждом чтении статус вычисляется из данных цепочки:

| Статус | Условие | Что отдаём |
|---|---|---|
| `NORMAL` | всё чисто | цену фида как есть |
| `OFF_HOURS` | фид молчит дольше порога, но все флаги чисты и разрыва цены нет | последнюю цену |
| `CORPORATE_ACTION` | `oraclePaused()`, либо `newUIMultiplier != uiMultiplier`, либо множитель сменился только что | цену, замороженную до входа в окно |
| `DESYNC` | нарушен инвариант непрерывности (§6) | замороженную цену |
| `TOKEN_HALTED` | `paused()` на токене | замороженную цену |
| `SEQUENCER_DOWN` | опциональный фид аптайма сообщает о простое | замороженную цену |
| `UNSAFE` | бюджет защиты исчерпан | **реверт** |

### Два состояния, которые нельзя знать наверняка

`OFF_HOURS` — **вывод, а не факт.** В Solidity нет календаря, а зашивать таблицу биржевых праздников в immutable-контракт означает гарантированное протухание. Поэтому состояние определяется от противного: фид молчит дольше порога, но обе паузы сняты, множитель в покое и инвариант непрерывности не нарушен. Отличить «биржа закрыта» от «оракул сломался» этим способом нельзя — и мы этого не утверждаем. Оба случая ведут к одинаково консервативному поведению, поэтому неразличимость безопасна: мы не выдаём молчание за свежую цену.

`SEQUENCER_DOWN` — **спящее состояние.** Фида аптайма на этой сети нет (§1.6), поэтому конструктор принимает адрес такого фида опционально, и нулевой адрес отключает проверку. Если Chainlink задеплоит фид позже, состояние включается новым деплоем адаптера без изменения логики. Заявлять эту защиту работающей сегодня нельзя.

### Почему щитом нельзя уклониться от честной ликвидации

Замороженная цена — это цена **до** входа в окно, одинаковая для всех участников. Позиция не может войти в окно в лучшем состоянии, чем была. Кто был под водой — остаётся под водой и остаётся ликвидируемым по той же цене. Окно не выдаёт никому бесплатный опцион; оно лишь запрещает утонуть из-за артефакта фида.

Это не политика, а арифметика: порядок здоровья позиций сохраняется тождественно. Свойство проверяется инвариант-фаззингом (§10).

### Почему защита ограничена по времени

Длительность паузы нам не подконтрольна — снятие ручное. Вечная заморозка означает неограниченный безнадёжный долг. Поэтому есть жёсткий бюджет, зашитый в конструкторе, после которого статус переходит в `UNSAFE` и адаптер реветит. Громко сломаться лучше, чем тихо врать.

## 6. Инвариант непрерывности

Главный технический аргумент продукта: мы перестаём зависеть от дисциплины эмитента.

При сплите цена токена **обязана быть непрерывной** — базовая акция падает в 10 раз, множитель растёт в 10 раз, цена токена не меняется. Зная предыдущий срез `(p₀, m₀)` и текущий `(p₁, m₁)`:

- `p₁/p₀ ≈ m₁/m₀` → множитель применён дважды;
- `p₁/p₀ ≈ m₀/m₁` → множитель применён к цене, базовая ещё не скорректирована;
- `|p₁/p₀ − 1|` выше порога в момент смены множителя → разрыв.

Любое из трёх включает защиту **независимо от флага `oraclePaused()`**.

Ложные срабатывания маловероятны: сплит даёт отношение 10 или 0.1, обычное движение рынка — единицы процентов. Пороги зашиты в конструкторе.

Цена решения: `latestRoundData()` — `view`, писать во время чтения нельзя, поэтому срез хранится и обновляется через `commit()`. Вызвать может кто угодно, привилегий это не даёт, но появляется зависимость от живости. Поведение при устаревшем срезе — деградация в `CORPORATE_ACTION` (консервативная сторона), а не в `NORMAL`.

## 7. Модель доверия и границы

**Власти нет ни у кого.** Ни владельца, ни ролей, ни прокси, ни апгрейда, ни возможности задать цену вручную. Исправление = новый деплой, клиент переключается сам.

**Чего продукт не делает (публикуется на сайте).** Заморозив цену, мы защищаем от ложной ликвидации, но не мешаем заёмщику **занять больше** под замороженную оценку, пока рынок реально падает. Оракул не видит, кто его вызвал.

Граница проходит так:

- защита ликвидаций — при **нуле правок** у клиента;
- защита от наращивания риска — три строки: гейт новых займов на `status() == NORMAL`. Опция.

**Вне области v1:** 159 токенов без фида. Ончейн-цены для них не существует, и адаптер её не создаёт. Это направление развития, а не обещание v1.

**Вне области v1:** защита от простоя секвенсора — фида аптайма в сети нет (§1.6).

## 8. Сайт (первый этап поставки)

**Аудитория: инвесторы и партнёры.** Главная страница ведёт нарратив рынка и неизбежности инфраструктуры; техническая глубина уходит в `/docs` и `/board`.

**Смысловой центр — не текст, а подлинность цифр.** Утверждение «фид молчит сутками» слабое. Живой счётчик «последнее обновление TSLA: 27 минут назад, допустимо до 24 часов» не требует доверия к нам вообще.

### Структура

- `/` — лендинг: заявление → живое доказательство в hero → масштаб (194 актива, 35 фидов, 159 токенов без ончейн-цены, 13 с изменённым множителем, сплит CRWD 4:1 уже в прошлом и притом без фида) → три сценария поломки → механизм → интеграция как diff в одну строку → границы продукта
- `/board` — живая доска: тикер, множитель, обе паузы, возраст цены, вычисленный статус
- `/docs` — гайд интеграции, семантика статусов, адреса
- `/api/feeds` — серверный маршрут: один Multicall3-вызов, кэш ~30 секунд, раздача всем посетителям

### Решения по сайту

- **Язык — английский.** Аудитория (инвесторы и протоколы в крипте) работает на нём, и терминология не требует калек.
- **Навбар — пять пунктов, как в §3 брифа.** Часть ведёт на якоря внутри лендинга, часть — на отдельные страницы. У пунктов 2 и 5 выпадашки по брифу.
- **Правая пара кнопок** заменяет `Login`/`Sign up` брифа на осмысленные для продукта без аккаунтов: вторичная и первичная CTA.
- **Hero во всю ширину**, без инсета — дефолт §12 брифа.
- **Кошелёк не подключается.**
- Брендовое имя не выбрано; вёрстка строится на плейсхолдере `{{BRAND}}` (2 слова, ~14 знаков), финальные строки закрываются после выбора имени.

### Ограничение честности

Пока контракты не задеплоены, сайт **не заявляет** существующий адаптер. Мониторинг и разбор проблемы подаются как рабочие (они рабочие); блок адаптера помечен как testnet/скоро и меняет метку по факту деплоя. Живые цифры всегда сопровождаются временем и адресом источника.

### Визуальное направление

**Определяется брифом `docs/hero-brief-2.md`, который имеет приоритет над этим разделом.**

Ранняя формулировка «плотный технический интерфейс, не 3D-сцена» отменена. Бриф задаёт тёмную кинематографичную сцену: почти чёрный фон с одним тёплым свечением, крупный органический 3D-объект с жидким металлическим шейдингом, обрезанный нижней границей секции, две стеклянные карточки поверх него. Ниже первого экрана страница становится тише — весь бюджет яркости потрачен в hero.

Обязательные к соблюдению правила брифа: золото и синева не существуют вне 3D-объекта; два начертания шрифта (400 и 600), никаких 300 и 700; два типа поверхностей и ровно два радиуса; заголовки секций выравниваются влево, по центру стоит только hero.

Стек брифа совпадает со §9: Next.js 16 + TypeScript + Tailwind v4 + `viem`.

### Стык брифа с ограничением честности

Правая стеклянная карточка hero по брифу — это «лейбл + число + полоса прогресса». Формат совпадает с нашими данными точно: число — возраст последнего обновления цены, полоса — доля исчерпанного суточного heartbeat. Лейбл карточки (11 px) обязан нести источник, иначе нарушается требование «живые цифры всегда с источником и временем».

Кнопка подключения кошелька (§6.3 брифа) **не нужна**: продукт read-only, библиотеки кошелька не подключаются.

## 10. Проверка

- юнит-тесты на каждый переход автомата состояний;
- **инвариант-фаззинг** на свойство «порядок здоровья позиций сохраняется» — центральное утверждение продукта, оно обязано быть проверено машиной, а не рассуждением;
- fork-тесты против мейннета: реальные CRWD (множитель 4.0), AAPL, TSLA и их фиды;
- сценарные тесты: сплит, реинвест дивиденда, обе паузы, выходные, исчерпание бюджета защиты, устаревший срез `commit()`, а также простой секвенсора против замоканного фида аптайма — чтобы спящее состояние было готово к включению;
- газовые бенчмарки пути `NORMAL` против прямого чтения Chainlink. Ориентир — 25–30k против ~10k, с быстрым путём при свежем срезе. Числа замеряются, а не обещаются.

## 12. Решения, принятые по умолчанию

Требуют подтверждения, но не блокируют работу над сайтом.

**Семантика `updatedAt` внутри защитного окна.** Адаптер возвращает текущее время, а `updatedAt` переопределяется как «момент, когда адаптер подтвердил, что значение безопасно использовать». Честное время наблюдения рынка доступно отдельно через `observedAt()`, а режим — через `status()`.

Обоснование: если возвращать реальное время раунда, у клиента срабатывает его собственная проверка свежести и он реветит — DoS не снимается, а лишь проходит сквозь адаптер, и щит теряет главную функцию. Переопределение семантики защитимо, но обязано быть громко задокументировано, иначе аудит справедливо запишет findings.

Альтернатива, если решение отменяется: два режима, выбираемые конструктором. Это дробит ликвидность адресов и удваивает матрицу тестов.
